# AvoidArc ⚡

원형 무대 위에서 붉은 전기선을 피하며 버티는 3D 서바이벌 게임.
닿으면 즉사, 버틴 초가 그대로 점수이고 전체 랭킹에 올라간다.

## 조작

| | |
|---|---|
| 이동 | 방향키 `← ↑ ↓ →` (WASD도 됨) — 평면 360° 자유 이동 |
| 점프 | `Space` — 공중에서 한 번 더 누르면 2단 점프 |
| 일시정지 | `Esc` |
| 모바일 | 화면 왼쪽 드래그로 이동, 오른쪽 `JUMP` 버튼 |

`Esc` 는 두 가지 일을 한다. 랭킹 창이 열려 있으면 그걸 닫고, 아니면
일시정지한다. 두 곳에서 따로 들으면 창을 닫으면서 동시에 일시정지가
걸리므로 `ui.js` 한 곳에서만 받는다.

**혼자 하기는 진짜로 멈춘다** — 시간도 전기선도 선다. **온라인 대전은
멈출 수 없다.** 서버가 계속 돌기 때문에 손을 놓으면 그 사이에 죽어 있다.
그래서 대전에서는 메뉴만 띄우고 게임은 그대로 흘리며, '다시 시작' 대신
'대전 포기'를 보여 준다.

## 전기선 패턴

시간이 지나면서 한 종류씩 해금되고, 속도도 함께 빨라진다.

| 해금 | 패턴 | 대응 |
|---|---|---|
| 0초 | **가로 훑기** — 무대를 직선으로 가로지른다 | 타이밍 맞춰 점프 |
| 12초 | **회전 빔** — 중앙을 축으로 도는 팔 | 중앙에서 벗어나 바깥쪽으로 |
| 28초 | **V자 조이기** — 양쪽에서 마주 보고 다가와 중앙에서 겹친다 | 겹치는 순간 점프 |
| 45초 | **격자 / 십자** — 직각으로 엇갈리는 두 줄기 | 빈틈을 찾아 서 있기 |

동시에 살아 있는 전기선은 스테이지별 `maxLive` 로 제한된다.
상한이 없으면 후반에 빠져나갈 틈이 아예 사라져서 실력과 무관하게 죽는다.

### 몰려 나오는 가로 훑기

28초부터는 가로 훑기가 가끔 **같은 방향에서 2~3줄**로 줄지어 온다.
스테이지 표의 `volley` 가 상한이고 `BEAM.volleyChance` 가 확률이다.

줄 사이는 **거리가 아니라 시간(`BEAM.volleyGap`)으로 벌린다.** 거리로 잡으면
후반에 빔이 빨라질수록 줄 사이를 지나갈 시간이 짧아져 넘을 수 없는 벽이 된다.
점프로 전기선 위에 떠 있는 시간이 약 0.58초라, 세 줄(간격 두 번 = 0.44초)까지가
한 번의 점프로 넘어갈 수 있는 한계다. `volleyGap` 을 키우면 착지했다 다시
뛰어야 하는데 그럴 여유가 없어서 그냥 못 피하는 패턴이 된다.

실제 발생률은 설정한 확률보다 낮다. 여러 줄이 `maxLive` 상한에 걸리면
그 판이 통째로 취소되고 다른 패턴을 새로 뽑기 때문이다.

발사 전 **0.85초 동안 노란 경고선**이 뜬다. 그 사이엔 맞지 않는다.

## 온라인 1v1

같은 무대에서 둘이 전기선을 피한다. **서로 밀칠 수 있고**, 마지막까지
살아남는 쪽이 이긴다. 상대 찾기는 무작위 매칭과 방 코드 둘 다 된다.

### 판정은 전부 서버가 한다

밀치기가 있으니 "누가 누구를 밀었는가"를 한 곳에서 정해야 한다. 각자
자기 화면에서 판정하면 둘 다 "내가 밀었다"고 우겨 화면이 어긋난다.
그래서 `lib/arena-match.js` 가 60Hz 로 물리를 돌리고 20Hz 로 상태를 뿌린다.

그런데 서버 응답을 기다렸다 움직이면 지연만큼 조작이 늦게 먹혀 점프
타이밍(0.58초 창)을 못 맞춘다. 그래서 `net.js` 는 내 캐릭터를 **먼저
굴려 보고**(예측), 서버 값이 오면 어긋난 만큼 슬쩍 당겨서 맞춘다.
2.5 이상 벌어지면 부드럽게 말고 그냥 순간이동시킨다. 상대는 예측할 수
없으니(입력을 모르니) 0.1초 과거를 보간해 그린다.

### 전기선은 통신으로 보내지 않는다

`shared/beams.js` 의 난수가 씨앗 기반이라, **씨앗만 맞춰 주면 서버와 두
클라이언트가 각자 똑같은 전기선을 만들어 낸다.** 대역폭이 크게 줄고
지연에도 강하다.

대신 조건이 하나 붙는다 — **세 곳이 같은 크기의 스텝을 같은 횟수만큼**
밟아야 한다. 그래서 클라이언트는 프레임 시간이 아니라 서버가 알려 준
경과 시간에 맞춰 `hazards.runToTick()` 으로 굴린다.

### 코드 구조

```
public/js/shared/   three.js 를 쓰지 않는 규칙. 브라우저와 서버가 같이 쓴다
  beams.js            전기선 패턴·난이도·판정 (씨앗 기반 난수)
  player-physics.js   이동/점프 물리와 밀치기
lib/arena-match.js  대전 한 판 (서버 시뮬레이션)
lib/lobby.js        WebSocket 연결·매칭·방
public/js/net.js    클라이언트 통신 (예측·보간)
public/js/versus-ui.js  대전 화면
```

**`shared/` 를 고칠 때는 양쪽에 다 영향이 간다.** 특히 물리를 바꾸면
예측과 서버 판정이 어긋나므로, 클라이언트만 고쳐 배포하면 안 된다.

### 배포 주의

WebSocket 은 HTTP 서버에 얹혀 있어 포트를 따로 열 필요가 없다. 다만
**Render 무료 플랜은 15분간 접속이 없으면 인스턴스가 잠든다.** 첫 접속이
30초쯤 걸리고, 자는 동안 진행 중이던 방은 사라진다. 방은 서버 메모리에만
두므로 재시작하면 모두 없어진다 (한 판이 길어야 2~3분이라 저장하지 않는다).

## 랭킹

트로피 버튼을 누르면 다섯 가지가 탭으로 나뉜다. 한 쪽에 10개씩 최대 10쪽(100위).

| 탭 | 무엇 | 어디서 |
|---|---|---|
| 버티기 | 혼자 하기에서 버틴 초 | `lib/scores.js` — 게스트도 오른다 |
| 다승 | 이번 시즌 1v1 승수 | `lib/users.js` — 로그인 계정만 |
| 승률 | 이번 시즌 1v1 승률 | `lib/users.js` — 로그인 계정만 |
| 연승 | 지금 달리고 있는 연승 | `lib/users.js` — 2연승부터 |
| 역대 | 끝난 시즌의 상위 3명 | `lib/scores.js` — 명예의 전당 |

**한 사람은 한 줄만 차지한다.** 잘하는 사람이 열 번 뛰면 열 자리를 채워서
랭킹이 그 사람 이름으로 도배된다. 새 기록이 들어오면 그 사람의 기존 줄을
갱신하되, **자기 최고를 넘었을 때만** 시간이 바뀐다. 못 넘으면 시도 횟수
(`runs`)만 올라가고 프로필의 "올린 기록"에 반영된다.

같은 사람인지는 계정은 id 로, 게스트는 이름으로 가른다(`samePerson()`).
이름으로도 보는 이유는 id 를 붙이기 전에 쌓인 옛 기록을 같은 사람으로
이어 주기 위해서다. 서버가 켜질 때 `dedupe()` 가 한 번 훑어 합친다.

**승률은 최소 판수를 넘겨야 오른다** (`MIN_RATE_GAMES`, 서버). 없으면 한 판
이기고 100% 로 1위가 되어 랭킹이 그 순간 의미를 잃는다. 배포 초기에는 낮게
잡아야 한다 — 한 판이 2~3분이라 100판이면 서너 시간이고, 사람이 붙기 전에는
아무도 못 채워 탭이 계속 비어 있다.

**연승은 지금 달리고 있는 것만 센다.** 한 번 지면 0 으로 돌아간다. 최고 연승은
따로 남지만 랭킹에는 쓰지 않는다 — 지나간 기록은 긴장을 만들지 않는다.

100위 밖이면 목록에는 없지만 아래에 "내 순위 N위" 로 따로 알려 준다.

게임이 끝나 기록을 올릴 때는 탭을 **버티기로 되돌린다.** 다승 탭을 보고
있었다면 시간 기록을 승수 형식으로 그리려다 깨지기 때문이다.

### 프로필

랭킹에서 **이름을 누르면** 그 사람의 기록이 열린다. 상단 바의 사람 버튼은
내 것을 연다. 둘 다 같은 화면이다 — 남의 프로필이라고 다르게 보여 줄
이유가 없고, 하나만 만들면 어긋날 일도 없다.

보여 주는 것: 최고 기록과 순위, 올린 기록 수, 이번 시즌 전적·승률·연승과
각 랭킹에서의 순위, 통산 전적. 승률 랭킹에 아직 못 올랐으면 몇 판
남았는지 알려 준다.

계정과 게스트를 같은 통로(`/api/profile?name=`)로 다룬다. 이름으로 사람을
특정할 수 있기 때문이다 — 계정 닉네임은 서로 겹칠 수 없고, 게스트는
`Guest####` 형식만 쓸 수 있어 계정이 그 이름을 가져갈 수 없다.

프로필 창은 랭킹(z 40)보다 **위에**(z 45) 뜬다. 같은 층에 두면 나중에
그려지는 랭킹이 덮어서, 이름을 눌러도 아무 일도 안 일어난 것처럼 보인다.
닫으면 아래의 랭킹이 그대로 남아 목록으로 돌아온다.

### 시즌

**시즌 = 달력의 한 달** (`lib/season.js`, 한국 시간 기준). 달이 바뀌면 지난
시즌의 상위 10명이 명예의 전당으로 옮겨 가고 랭킹은 비워진다. 대전 전적도
이번 시즌 칸이 0 으로 돌아간다(통산 전적은 남는다).

영원히 쌓아 두면 1위가 한 번 정해진 뒤로는 아무도 못 넘어서 랭킹이 굳는다.

**달이 바뀌는 순간을 노리지 않는다.** 그 시각에 서버가 떠 있으리란 보장이
없고, 반대로 몇 달 꺼져 있다 켜질 수도 있다. 대신 기록을 만질 때마다
(`rollSeasons()`, `freshSeason()`) 지난 시즌 것이 섞여 있는지 확인한다.

**개인 최고 기록은 초기화하지 않는다.** 그건 브라우저에 있고 캐릭터 해금의
근거다. 시즌마다 지우면 캐릭터가 도로 잠긴다.

## 관리

들어가는 길이 둘이다. 하는 일은 겹치지만 쓰는 상황이 다르다.

| | 어떻게 들어가나 | 언제 쓰나 |
|---|---|---|
| `/admin.html` | 열쇠(`ADMIN_TOKEN`) | 로그인 없이, 다른 기기에서 |
| 게임 안 🛠 버튼 | 관리자 계정으로 로그인 | 평소에 |

**누가 관리자인지는 `.env` 로 정한다.** 코드에 계정을 박아 두면 저장소에
남고, 관리자를 바꿀 때마다 배포해야 한다.

```
ADMIN_NICKNAMES=admin        쉽다. 닉네임을 바꾸면 관리자에서 풀린다.
ADMIN_USER_IDS=<계정 id>     안전하다. 닉네임을 바꿔도 유지된다.
```

배포하면 Render 대시보드의 환경변수에 같은 값을 넣는다.

할 수 있는 일: 기록 삭제, 계정 전적 초기화(닉네임과 계정은 남는다),
접속자 수 확인.

목록은 **한 쪽에 10줄씩 쪽으로 나눈다.** 사람이 늘수록 스크롤로는 못 찾는다.
쪽만 나눠도 100명 중 하나를 찾으려면 쪽을 계속 넘겨야 하므로 이름 검색을
같이 뒀다. `PER_PAGE` 를 늘리면 안 된다 — 창(84vh)에 머리말·탭·검색칸까지
들어가는 최대치가 10줄이고, 넘기면 쪽번호가 화면 밖으로 밀려나 쪽을
넘길 수가 없다.

**`.modal-card` 안의 요소는 `flex: none` 을 붙여야 한다.** 세로 flex 라
목록이 길어지면 자식이 눌려서 탭·검색칸·쪽번호가 얇은 띠로 찌그러진다.
높이가 0 이 아니라 8px 쯤으로 남아서, 화면만 봐서는 "왜 탭이 안 보이지"
하고 넘어가기 쉽다.

### 부정행위 살펴보기

계정 목록에서 **대전 기록**을 누르면 그 사람이 치른 판이 나온다.
누구와, 몇 초 동안, 무작위 매칭인지 방 코드인지까지.

승패 숫자만으로는 판단할 수 없다. "20승 3패"가 정상인지 짜고 친 것인지
알려면 **누구와 몇 초 동안 했는지**가 남아야 한다 (`lib/matches.js`).

1v1 판정은 서버가 하므로(`lib/arena-match.js`) 클라이언트가 결과를 조작할
수는 없다. 실제로 문제가 되는 건 **두 계정이 짜고 한쪽만 계속 이겨 주는
쪽**이라, 네 가지를 계산해 수상하면 붉게 물들인다.

| 신호 | 붉어지는 기준 | 왜 |
|---|---|---|
| 같은 상대 | 70% 이상 (5판~) | 한 사람과만 붙었다 |
| 방 코드 비율 | 90% 이상 (5판~) | 무작위 매칭을 피했다 |
| 짧은 승리 | 이긴 판의 50% 이상 (3승~) | 상대가 일부러 떨어져 줬다 |
| 평균 시간 | 10초 미만 | 판이 통째로 너무 짧다 |

기준은 `admin-ui.js` 에 있다. **판단은 사람이 한다** — 화면은 근거만 모은다.
친구와 방 코드로만 놀아도 신호는 켜지므로, 숫자 하나로 단정하면 안 된다.

기록은 최근 3000판까지 남는다(`MAX`). 게스트끼리 한 판은 남기지 않는다 —
계정이 없어 살펴볼 대상 자체가 없다. 그리고 **이 기능을 넣기 전의 대전은
남아 있지 않다.**

**버튼을 감추는 건 보안이 아니다.** 관리자가 아니면 상단 바에 🛠 이
안 보이지만, 그것만으로는 아무것도 막지 못한다. 실제로 막는 건 서버의
`requireAdmin` 이고, 열쇠와 관리자 계정 둘 중 하나가 맞아야 통과한다.
비로그인·일반 사용자는 모든 관리 경로에서 401 을 받는다.

## 실행

**Node 22 이상**이 필요하다. 데이터베이스로 `node:sqlite` 를 쓰는데,
그게 Node 22 부터 들어왔다.

```bash
npm install      # express + three (three 는 개발 의존성)
npm run vendor   # three.js 빌드를 public/js/vendor/ 로 복사 (이미 커밋되어 있음)
npm start        # http://localhost:3000
```

`npm run dev` 는 파일이 바뀌면 서버를 다시 띄운다.

조합이라 에셋 파일 없이 바로 뜬다.

## 저장소

랭킹·계정·대전기록이 SQLite 파일 하나(`data/avoidarc.db`)에 들어간다.
`node:sqlite` 는 Node 에 들어 있어서 따로 설치하거나 빌드할 게 없다 —
어느 호스팅에 올려도 그대로 돈다.

### 왜 JSON 파일을 그만뒀나

전에는 저장소마다 JSON 파일 하나를 통째로 읽고, 뭘 하나 바꿀 때마다
파일 전체를 다시 썼다. 계정이 늘면 이게 그대로 비용이 된다. 재 봤다:

| 계정 수 | 전적 1건 저장 | 내 순위 계산 |
|---|---|---|
| 100명 | 1.2ms → **0.13ms** | – |
| 1,000명 | 2.1ms → **0.17ms** | – |
| 10,000명 | 13ms → **0.18ms** | – |
| 50,000명 | **67.2ms → 0.20ms** | **70.9ms → 0.78ms** |

5만 명이면 대전 한 판이 끝날 때마다 17MB 를 다시 썼다. 쓰기가 줄까지
서서, 사람이 몰리는 순간에 제일 느려진다.

**게임 계산은 병목이 아니었다.** 대전 400판을 동시에 돌려도 코어 하나의
0.4% 만 쓴다. 사람이 늘 때 무너지는 건 저장 쪽이다.

### 옮기면서 배운 것

- **읽는 길에서 쓰지 않는다.** 처음에는 랭킹을 뽑기 전에 전 계정의 시즌
  칸을 UPDATE 로 맞췄다. 5만 명에서 46ms 가 나왔다. 지금은 읽을 때
  0 으로 보여 주기만 하고, 실제로 내려 쓰는 건 그 계정의 전적이 바뀌는
  순간뿐이다.
- **필요한 만큼만 가져온다.** 랭킹이 조건에 맞는 전부(5만 중 4만 8천)를
  객체로 만들어 돌려주고 서버가 100개만 쓰고 버렸다. `LIMIT` 을 걸고,
  내 순위는 목록에서 찾지 않고 `COUNT` 로 센다.
- **`WHERE` 를 인덱스에 같이 새긴다.** `nickname IS NOT NULL` 이 인덱스에
  없으면 후보마다 실제 줄을 꺼내 확인한다. 부분 인덱스로 바꾸자
  내 순위 계산이 71ms 에서 0.78ms 가 됐다.

### 예전 JSON 에서 옮기기

서버를 켜면 `scores.json` / `users.json` / `matches.json` 이 남아 있는지
보고 한 번만 옮긴다. 옮긴 원본은 `.imported` 로 이름만 바꿔 둔다 —
지우지 않는다.

### 백업

```bash
node scripts/backup.js
```

**파일을 그냥 복사하면 안 된다.** WAL 방식에서는 최근 쓴 내용이 아직 본
파일이 아니라 `-wal` 에 있다. 재 봤더니 5000행 중 4MB 가 WAL 에 있었다 —
본 파일만 복사했으면 대부분을 잃었을 것이다. `scripts/backup.js` 는
`VACUUM INTO` 로 지금 상태를 한 덩어리로 정리해 뜬다. **서버를 멈추지
않아도 된다.**

`.env` 에 `BACKUP_UPLOAD` 를 적어 두면 백업 뒤에 그 명령을 실행한다.
`{file}` 자리에 방금 뜬 파일 경로가 들어간다.

```
BACKUP_UPLOAD=rclone copy {file} gdrive:avoidarc-backup
```

**서버 안에만 두면 절반짜리다.** 서버가 사라지면 백업도 같이 사라진다.
Oracle 무료 서버는 오래 놀면 회수될 수 있어서 특히 그렇다.

만들면서 잡은 것들 — 전부 "잘 돌아가는 것처럼 보이는" 실패였다:

- **같은 시각에 두 번 뜨면 통째로 실패했다.** 이름이 겹치면
  `VACUUM INTO` 가 예외를 던진다. 손으로 두 번 돌리는 건 흔한 일이다.
- **뒤에 `-1`, `-2` 를 붙였더니 정렬이 깨졌다.** `-` 가 `.` 보다 작아서
  `-1` 이 원본보다 앞으로 간다. 파일 시각까지 같아서 무엇이 최신인지
  알 수 없어지고, 그 상태로 정리를 돌리면 **방금 뜬 백업을 지운다.**
  이름에 밀리초를 넣어 이름 자체가 시간 순서가 되게 했다.
- **오래된 것 하나를 못 지우면 백업 전체가 실패로 끝났다.** 파일이
  잠겨 있으면 그럴 수 있는데, 백업은 이미 떠 있었다. 정리 실패는
  경고만 남기고 넘어간다.

## 무대

해질녘 공중에 떠 있는 풀섬. 잔디 상판, 흙 절벽, 가장자리를 두른 밝은 돌,
늘어진 뿌리, 떠다니는 반딧불이와 꽃가루, 멀리 깔린 작은 섬들로 이루어진다.

색은 붉은 전기선이 묻히지 않는 선에서 정했다. 잔디는 채도를 눌러 어둡게,
하늘은 위가 짙고 아래만 노을빛이다. 밝은 대낮으로 만들면 발광하는
전기선이 배경에 파묻혀 안 보인다.

잘 틀리는 자리:

- **원뿔에 텍스처를 입히지 말 것.** 꼭짓점에서 UV 가 뭉개져 삼각형으로
  갈라진다. 끝을 조금 남긴 원통(`CylinderGeometry`)을 쓴다.
- **떠 있는 무대에 땅에 선 나무를 두면** 허공에 박힌 것처럼 보인다.

### 성능 — 여기부터 확인할 것

무대를 꾸미다 렉이 생기면 십중팔구 이 둘이다.

| | 한도 | 왜 |
|---|---|---|
| 실시간 조명 | **8개 이하** | 조명이 하나 늘 때마다 화면의 모든 픽셀이 그 계산을 더 한다. 반딧불이마다 `PointLight` 를 달았다가 24개가 돼서 프레임이 무너진 적 있다. 빛나 보이는 건 스프라이트로 충분하다. |
| 드로우콜 | **100 안팎** | 같은 모양을 여러 번 놓을 땐 반드시 `scatter()`(InstancedMesh)를 쓴다. 돌 46개를 따로 만들면 그것만으로 46번 그린다. |

그림자는 플레이어만 만든다. 장식까지 켜면 그림자 맵을 굽는 패스에 전부
다시 그려진다.

측정은 `renderer.info` 로 한다 — `render.calls`, 씬을 훑어 센 조명 수,
`castShadow` 개수. 현재 값은 드로우콜 80 / 조명 8 / 그림자 4.

## 소리

점프·2단점프·착지·경고·전기·감전·낙사·스테이지 상승 효과음과, 바람과
풀벌레 소리로 된 환경음이 들어 있다. 우측 상단 버튼으로 끄고 켜며,
설정은 `localStorage` 에 남는다.

기본값은 `audio.js` 가 Web Audio 로 그때그때 **합성**한다. 오디오 파일이
없으니 받을 것도 기다릴 것도 없다.

### 내 소리로 바꾸기

1. 파일을 `public/sounds/` 에 넣는다
2. `config.js` 의 `SOUNDS` 에 경로를 적는다

```js
export const SOUNDS = {
  jump: './sounds/jump.mp3',
  zap: { url: './sounds/zap.wav', volume: 0.7 },   // 소리별 크기 조절
  music: './sounds/bgm.mp3',                        // 반복 재생
  land: null                                        // null 이면 합성음
};
```

브라우저가 읽을 수 있는 형식이면 된다 (mp3 / ogg / wav / m4a).
**일부만 바꿔도 된다** — 지정하지 않은 것은 합성음 그대로 쓴다.
파일이 없거나 형식이 안 맞으면 콘솔에 경고를 남기고 합성음으로 돌아가므로
게임이 멈추지는 않는다.

`ambient` 는 환경음(바람·풀벌레)을 통째로 대체하고, `music` 은 그 위에
겹쳐 흐른다. 둘 다 반복 재생된다.

파일은 페이지를 열 때 미리 내려받아 두고, 소리를 열 수 있게 되는 첫
클릭 때 해독한다. **브라우저는 사용자가 뭔가 누르기 전에는 소리를 못 내게
막기 때문에** `AudioContext` 를 그때 만들 수밖에 없다.

**브라우저는 사용자가 뭔가 누르기 전에는 소리를 못 내게 막는다.** 그래서
`AudioContext` 는 게임 시작 버튼을 누르는 순간 `unlock()` 에서 만든다.
소리를 다른 데서 먼저 내려고 하면 조용히 무시된다.

물리와 연출 쪽은 소리를 모른다. `player.onJump` / `hazards.onFire` 처럼
사건만 알려 주고, 무슨 소리를 낼지는 `main.js` 가 정한다.

## 캐릭터

여섯 종을 도형만으로 조립한다. 그림 파일이 없다.

| | 해금 | 머리 |
|---|---|---|
| 🌱 만드라고라 | 처음부터 | 잎 5장 |
| 🥕 당근 | 30초 | 잎 7장 |
| 🍄 버섯 | 60초 | 빨간 갓 + 흰 점 |
| 🌰 도토리 | 90초 | 갈색 모자 + 꼭지 |
| 🌵 선인장 | 120초 | 가시 + 머리 꽃 |
| 🥔 감자 | 150초 | 싹 3개 |

- `characters.js` — 몸통 옆모습·색·머리 장식·해금 조건을 적은 표
- `plant.js` — 그 표를 읽어 실제로 조립. 몸통은 `LatheGeometry`,
  잎은 캔버스 텍스처를 살짝 휜 판에 입힌 것, 외곽선은 뒤집힌 껍데기
- `char-ui.js` — 고르는 화면. 미리보기 그림은 **실제 캐릭터를 작은
  렌더러로 한 번 찍어서** 쓴다. 캐릭터를 고치면 미리보기도 같이 바뀐다

해금은 **최고 기록으로 그때그때 계산**한다. 따로 저장하지 않으므로
어긋날 일이 없다. 고른 캐릭터만 브라우저에 저장한다.

### 크기는 몸통 폭으로 맞춘다

**모든 캐릭터의 몸통 폭이 같아야 판정이 공평하다.** 전기선은 y 0.38~0.82
에만 있어서 판정에 걸리는 건 몸통 폭뿐이고, 머리 위로 얼마나 솟든 상관없다.

전체 높이로 맞추면 안 된다. 머리 장식이 작은 캐릭터(도토리)는 그만큼
몸이 커져서 **"스쳤는데 안 죽는" 유리한 캐릭터**가 된다. 실제로 그렇게
만들었다가 몸통 폭이 0.98~1.81 로 벌어지는 걸 확인하고 고쳤다.

`avatar.js` 의 `normalizeByBody()` 가 이 일을 한다.

### 건드릴 때 주의할 것

- **`LatheGeometry` 의 옆모습 점은 아래에서 위로 적는다.** 거꾸로 적으면
  면이 안팎으로 뒤집혀 겉이 사라지고 테두리 껍데기만 남아 새까맣게 보인다.
- **회전체를 난수로 울퉁불퉁하게 만들지 않는다.** 한 바퀴 돌아 만나는
  이음매에 같은 자리 정점이 두 벌 있어서, 둘이 따로 밀리면 몸에 세로로
  금이 쭉 간다. `roughen()` 은 각도의 sin/cos 으로만 흔들어 저절로 맞물리게 한다.
- **눈·볼은 표면에서 재서 얹는다.** `표면z * 0.8` 같은 비율을 쓰면 몸이
  굵을수록 깊이 파묻힌다 — 선인장 눈이 통째로 몸 안에 들어가 실눈이 됐었다.
- 잎 피벗은 `rotation.order = 'YXZ'` 여야 한다. 기본 `'XYZ'` 는 Y 를 먼저
  적용해서, 방향과 무관하게 잎이 전부 같은 쪽으로 기울어진다.
- 잎은 완전한 평면이면 옆에서 볼 때 실선 하나로 사라진다. `makeLeafGeometry()`
  가 살짝 휘어 놓는 이유다.
- **재질을 캐릭터끼리 나눠 쓰지 않는다.** 캐릭터를 갈아 끼울 때
  `disposeTree()` 가 옛 몸의 재질을 버리는데, 그게 공유물이면 화면에 남아
  있는 상대 캐릭터까지 같이 망가진다. 1v1 에서만 드러나는 종류의 사고다.
- 미리보기용 렌더러는 **하나를 돌려 쓴다.** WebGL 컨텍스트는 브라우저마다
  개수 제한이 있어 캐릭터 수만큼 만들면 위험하다.

### 점프 소리 녹음

점프할 때 **내가 녹음한 목소리**가 난다. 타이틀 화면 아래, 조작키 안내
옆 칸에서 바로 녹음한다.

2단 점프에서도 나되 **조금 더 높은 음**으로 낸다(`VOICE.doubleRate`).
같은 소리를 0.2초 간격으로 두 번 그대로 틀면 말을 더듬는 것처럼 들린다.

목소리는 **캐릭터마다 두지 않는다.** 하나를 녹음해 두면 어떤 캐릭터로
뛰든 그 소리가 난다.

- `recorder.js` — 마이크(`getUserMedia` + `MediaRecorder`)
- `voice-store.js` — 녹음 원본을 IndexedDB 에 보관
- `voice-ui.js` — 타이틀 화면의 녹음 칸
- `audio.trim()` — 앞뒤 무음을 잘라내고 크기를 맞춘다

받은 소리를 그대로 쓰면 안 된다. 사람은 버튼을 누르고 숨을 고른 뒤에
말하기 때문에, 안 자르면 점프하고 한참 뒤에 소리가 난다.

**귀엽게 들리는 건 재생 속도** 덕이다. `playbackRate` 를 올리면 음이
같이 올라가 만화 목소리가 된다. `VOICE.userRate`(1.25) 로 고정돼 있고,
`1.0` 으로 두면 녹음한 그대로 나온다.

마이크는 **안전한 연결에서만** 열린다. `localhost` 는 예외로 허용되지만
배포한 사이트라면 https 여야 한다.

녹음은 브라우저에 붙는다. 기기를 옮기면 따라오지 않고, 1v1 에서도
상대에게는 들리지 않는다.

### 같은 도형을 여러 개 뿌릴 땐 인스턴싱

선인장 가시를 `Mesh` 로 하나씩 만들었더니 그것만으로 드로우콜이 마흔 개
넘게 늘었다. `scatterInstances()` 로 묶어서 한 번에 그린다. 지금은 캐릭터
하나당 26~32 콜로 고르다.

### 다른 모델로 바꾸기

1. `.glb`(또는 `.gltf`) 파일을 `public/models/` 에 넣는다
2. `config.js` 의 `AVATAR.url` 을 그 경로로 바꾼다

```js
export const AVATAR = {
  url: './models/hero.glb',
  yaw: 0,             // 모델이 엉뚱한 곳을 보면 Math.PI 등으로 돌린다
  animation: null,    // 클립 이름. null 이면 첫 번째 클립
  yOffset: 0          // 발이 안 붙을 때 미세 조정
};
```

**모델 크기와 원점은 신경 쓰지 않아도 된다.** 로더가 실제 크기를 재서
높이를 `PLAYER.height`(2.0)에 맞추고, 발바닥을 바닥에, 좌우 중심을 원점에
정렬한다. 애니메이션이 들어 있으면 자동 재생된다.

파일이 없거나 형식이 안 맞으면 콘솔에 경고를 남기고 **만드라고라로
돌아간다.** 게임은 어느 쪽이든 그대로 돌아간다.

물리와 판정은 겉모습과 완전히 분리돼 있어서, 모델을 바꿔도 히트박스는
`PLAYER.radius`/`PLAYER.height` 그대로다.

> Draco 압축이나 KTX2 텍스처를 쓴 모델은 별도 디코더가 필요해서 지금은 못
> 읽는다. 내보낼 때 압축을 끄면 된다.

### 캐릭터 연출 구조 — 건드릴 때 주의

- `Player.mesh` = 위치와 바라보는 방향
- `Player.rig` = 기울기·공중제비·찌그러짐. **원점이 몸 한가운데(발바닥에서
  `height/2` 위)** 에 있다
- `Player.skin` = 겉모습. 리그 안에서 갈아 끼운다

리그 원점이 발바닥에 있으면 공중제비가 몸을 반지름 `height` 짜리 원으로
휘둘러서 회전이 아니라 발작처럼 보인다. 기울기와 회전을 한 `rotation.x` 에
같이 쓰는 것도 같은 이유로 안 된다 — 서로 값을 덮어써서 프레임마다 튄다.

### 닉네임

`public/js/profanity.js` 를 **브라우저와 서버가 같이 쓴다.** 브라우저 검사는
입력하는 동안 바로 알려 주기 위한 것이고, 실제로 막는 건 서버다.
클라이언트 검사는 우회할 수 있으니 서버에서 반드시 한 번 더 통과시킨다.

- 최대 10자 (이모지는 코드 단위가 둘이라 `Array.from` 으로 센다)
- 비우면 `익명`
- 욕설·음란 표현 차단

흔한 우회까지 잡는다: 기호·띄어쓰기 끼우기(`ㅅ.ㅂ`), 숫자 치환(`sh1t`,
`시1발`), 글자 늘이기(`씨이이이발`). 검사 문자열을 두 벌(숫자를 글자로
되돌린 것 / 숫자를 지운 것) 만들어 둘 다 보고, 사이에 낀 글자 2개까지
허용하는 느슨한 일치를 쓴다.

`ALLOW` 목록은 반대 방향 보정이다. `Essex` 가 `sex` 때문에 걸리므로
멀쩡한 낱말을 검사 전에 들어낸다. **작정하고 우회하는 건 못 막는다** —
거기까지는 수동 삭제의 몫으로 뒀다.

> **점수는 클라이언트가 보고한다.** 개발자 도구로 임의의 값을 올릴 수 있다.
> 서버가 플레이를 다시 검증하지 않는 한 원천 차단은 불가능하다. 그래서
> 막는 대신 **사후에 지우는** 관리 화면을 뒀다.

## 로그인 (Google / Apple)

로그인하면 닉네임이 계정에 묶이고, 1v1 **승패가 쌓인다.**
로그인은 선택이다 — 게스트로도 그대로 놀 수 있고, 그때는 닉네임을
직접 적고 전적은 남지 않는다.

**설정하지 않으면 로그인 버튼 자체가 안 뜬다.** Google 만 켜도 되고,
Apple 은 나중에 붙여도 된다.

### 준비물

| | |
|---|---|
| Google | [Cloud Console](https://console.cloud.google.com) 에서 OAuth 클라이언트 생성. **무료**, localhost 로도 개발 가능 |
| Apple | Apple Developer Program **연 $99**, 그리고 **HTTPS 도메인 필수** (localhost 불가) |

### 설정하는 법

`.env.example` 을 `.env` 로 복사하고 값을 채우면 `npm start` 가 알아서
읽는다. `.env` 는 `.gitignore` 에 들어 있어 저장소에 올라가지 않는다.

```bash
cp .env.example .env
```

```bash
BASE_URL=http://localhost:3000        # 리디렉트 주소의 기준
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

Google Cloud Console 에서 **웹 애플리케이션** 유형으로 OAuth 클라이언트를
만들고, 승인된 리디렉션 URI 에 `<BASE_URL>/auth/google/callback` 을 넣는다.
(Apple 은 `/auth/apple/callback`.)

**배포하면 `BASE_URL` 을 실제 주소로 바꾸고, 제공자 콘솔의 리디렉션 URI 도
같이 고쳐야 한다.** 둘이 어긋나면 로그인이 거부된다.

### 설계 메모

- 계정을 가르는 열쇠는 **(제공자, 제공자쪽 사용자 ID)** 쌍이다. 이메일로
  가르면 사용자가 이메일을 바꿨을 때 남남이 된다.
- 세션은 **HttpOnly 쿠키**다. 자바스크립트가 못 읽으니 XSS 로 훔쳐가지
  못한다. 대신 "지금 누가 로그인했는지"는 `/api/me` 로 물어봐야 한다.
- `state` 파라미터로 CSRF 를 막는다. 없으면 남이 만든 로그인 링크를 눌러
  **남의 계정으로 로그인되는** 일이 생긴다.
- `id_token` 의 서명은 검증하지 않는다. 토큰 엔드포인트에서 **TLS 로 직접
  받아 온** 것이라 중간에 낄 사람이 없기 때문이다. (브라우저를 거쳐
  받은 토큰이라면 반드시 검증해야 한다.)
- **로그인한 사람의 이름은 서버가 정한다.** 브라우저가 보낸 이름은 기록
  등록에서도 대전에서도 무시한다. 안 그러면 로그인한 채로 남의 이름을
  사칭할 수 있다.
- 닉네임은 대소문자를 무시하고 **중복을 막는다.** `Alex` 와 `alex` 가
  따로 있으면 랭킹에서 누가 누군지 알 수 없다.

### 진짜 계정 없이 시험하기

`GOOGLE_AUTH_URL` / `GOOGLE_TOKEN_URL` 을 지정하면 그쪽을 제공자로 쓴다.
같은 흐름을 말하는 가짜 서버를 세워 두면 로그인 전체를 로컬에서
끝까지 돌려 볼 수 있다. **평소에는 지정하지 않는다.**

## 랭킹 관리 (`/admin.html`)

조작된 기록이나 부적절한 닉네임을 지우는 화면.

| | |
|---|---|
| `GET /api/admin/scores` | 전체 기록 (등록 시각 포함) |
| `DELETE /api/admin/scores/:id` | 하나 삭제 |
| `POST /api/admin/scores/clear` | 전체 삭제. 본문에 `{"confirm":"DELETE ALL"}` 필요 |

모두 `x-admin-token` 헤더가 있어야 한다. 열쇠 비교는 `timingSafeEqual` 로
한다 — `===` 로 비교하면 앞 몇 글자가 맞았는지가 응답 시간에 새어 나온다.

**열쇠 정하는 순서**

1. 환경변수 `ADMIN_TOKEN` 이 있으면 그걸 쓴다 → **배포할 땐 반드시 이렇게**
2. 없으면 `data/admin-token.txt` 를 읽는다
3. 그것도 없으면 새로 만들어 저장한다 (서버 콘솔에 찍힌다)

2·3번은 로컬 편의용이다. `data/` 는 `.gitignore` 에 들어 있어 저장소에
올라가지 않지만, Render 무료 플랜은 디스크가 휘발성이라 재배포 때마다
열쇠가 바뀐다. 배포 환경에서는 `ADMIN_TOKEN` 을 지정해야 한다.

목록에서 다른 기록보다 유독 튀는 값(중앙값의 4배 또는 180초 이상)에는
**확인 필요** 표시가 붙는다. 조작 판정이 아니라 눈으로 확인해 보라는
표시일 뿐이다.

## 배포 (Render.com)

`render.yaml` 이 있어서 저장소를 연결하면 바로 뜬다.
**Render 대시보드에서 `ADMIN_TOKEN` 값을 넣어야** 관리 화면에 들어갈 수 있다.

**무료 플랜은 디스크가 휘발성이라 재배포/재시작 때 랭킹이 초기화된다.**
기록을 유지하려면 유료 플랜에서 디스크를 붙이고 `render.yaml` 의 `DATA_DIR`
과 `disk:` 블록 주석을 함께 해제한다. 규모가 커지면 `lib/scores.js` 를
Postgres 같은 외부 DB로 갈아 끼우면 된다.
